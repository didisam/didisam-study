### 1. 슬래시 커멘드

```
/status
```

- 확인할 수 있는 것
  - 세션 ID
  - 컨텍스트: 지금 이 세션에서 코덱스가 기억할 수 있는 총 용량, 이 용량이 찰 수록 코덱스 성능 및 결과물 품질 떨어질 수 있음.
    하지만 코덱스는 이를 자동으로 정리해주는 기능이 있어 클로드보다 상대적으로 신경을 덜 써도 됨
  - 남은 사용량 등

- 스티어링
  - enter : 현재 작업에 추가 지시 전달(혹은 방향 전환)
  - tab : 현재 작업이 끝난 뒤 처리하도록 대기열에 추가

```
/init
```

- 프로젝트 루트에 AGENTS.md 초안

```
/plan
```

- 플랜모드 활성화

```
/ide
```

- 지금 열린 ide(ex. vscode)와 터미널 활성화
- 지금 드래그로 선택한 코드에 대해 설명해줘 처럼 사용 가능
- 다시 입력 시 해제됨

```
/permission
```

- 코덱스가 하나하나 승인 받게 할 지, 코덱스 자율에 맡길 지 등을 선택할 수 있다

```
/model
```

- 모델 선택 가능

```
/compact
```

- 한 세션의 컨텍스트 용량 많이 찼을 때, 대화 압축 - 토큰 아낌 - 답변 품질 높임
- 자동으로 컴팩트를 하므로 우리가 할 일은 별로 x

```
/statusline
```

- codex 화면에 표시될 걸 스페이스바로 선택할 수 있다
- 잔여 사용량, 모델 등

```
/copy
```

- 코덱스 마지막 응답을 클립보드로 복사하는 명령

```
/goal
```

- 정확한 요구사항이 있을 때 해당 모드로 작업 진행 가능

```
/diff
```

- git diff 기반 동작
- 코덱스가 수정한 변경사항을 diff로 확인할 수 있다.

```
/review
```

- 작업 트리나 기준 브랜치 대비 변경사항을 코드 리뷰 모드로 점검

### 2. 하네스 엔지니어링이란

- 하네스: 말에게 채우는 벨트, 주인의 의도대로 움직이도록 하는 안전 장치
- 조건을 반복해서 말하는 것 x, 조건을 담은 시스템을 미리 만들어두는 것

#### AGENTS.md

- 지속적으로 사용될 규칙
- ~/.codex/AGENTS.md
  - 개인 선호
  - 팀/레포 규칙은 레포 루트에 AGENTS.md에 작성
- 너무 길게 x, 기본 합산 한도 32KiB, 필요하면 하위 디렉토리별로 쪼개기
- 강제 가능한 건 AGENTS.md 작성만 하지말고 도구도 사용(pre-commit, linter, type checker 등)
- 검증 절차 역시 명확히 작성 -> ex. js 수정 후 npm test
- 계층별로 작성해서 에이전트가 작업에 필요한 부분만 읽고 일하도록 구성

#### config.toml

- 코덱스의 설정이 작성되는 곳
- 내 컴퓨터에서는 코덱스가 기본적으로 어떻게 동작해야하는가
- ~/.codex/config.toml
  - toml: 문서 형식, 프로그램 설정들 작성할 때 많이 사용
- 모델, 추론레벨, 서비스 티어(fast, default), 플러그인 기능 활성화 여부

#### SKILL.md

- 특정 업무에 대한 메뉴얼
- 스킬의 메타데이터와 작업지침
- Skill Creator로 생성 가능
- Skill Installer + 깃헙 주소 로 다른 사람이 만든 스킬을 다운 받을 수 있다
  - 깃헙에 codex skill로 검색하면 유용한 스킬들 찾을 수 있다!
